# Design

## Context

See proposal.md for motivation and issue scope. `tools/gen-scheme-base.ss` imports Chez, loads the declaration from a fixed path, and writes every partition member. `src/core.ss` independently computes exports and bodies through `library-export-names`, `library-body-forms`, and `partition-library-form`. `tools/regen.sh` embeds raw prelude text; the batch entry and several REPL paths read it to compile the baked set. Only the declaration decides membership, baked status, dependencies, and destination paths.

The existing whole-file generation guard skips without Chez. The Chez-free surface guard cannot establish body freshness. Compiler input accounting already includes generation scripts and declared generated members; the new assembly pieces must join that accounting. Several module-system requirements explicitly prescribe the old two-derivation representation and need delta updates. Their old prohibition on private macros contradicts the current generator, which deliberately permits them.

## Goals / Non-Goals

**Goals:** Remove the duplicate library construction algorithm while retaining host parity, source-order-sensitive compilation, pure compiler-core behavior, and deterministic bootstrap convergence. Make the generator's correctness checks independently observable.

**Non-Goals:** Changing public bindings, cache interface formats without necessity, expanding the baked set, or adding `load`, `eval`, directory-creation primitives, or a new runtime dependency. No guaranteed size reduction: record measurements and explain any increase.

## Decisions

### 1. One portable generator with thin host orchestration

Move construction, validation, and serialization into shared flat Scheme accepted by both hosts. A shell wrapper prepares an isolated program by concatenating the selected declaration and shared generator with a host-specific import/entry layer. This replaces dynamic `load` without parsing or evaluating arbitrary Scheme data as declarations. Validate fixture declarations as source in the same manner. Explicit options select prelude input, declaration input, and output root; preserve the existing default inputs and out-root invocation through a compatibility wrapper where needed.

Shell orchestration creates declared output directories; Scheme writes the files. Use existing read/file/process-context facilities and portable output operations instead of Chez `fprintf`, printer parameters, and replace-mode output ports. Both hosts use one canonical serializer for datum spellings where host `write` differs (especially strings, characters, symbols, and numeric constants). Preserve existing generated bytes where possible; any deliberate canonicalization affects both hosts and is reviewed separately from semantic changes.

Alternative: add `load` or a general evaluator to Emit. That would expand language and runtime scope solely for a developer tool. Alternative: maintain two generators. That preserves the duplication this change is meant to remove.

### 2. Embed generated forms for the complete baked set

Generate the entire declared partition, but embed only entries marked baked, in their declared dependency order. Assembly produces a named collection of generated library source strings or equivalent readable forms with explicit library identity. The declaration remains authoritative for membership; validate each generated form's name and imports against it before embedding. Do not hardcode a two-member list or concatenate members into a source treated as one library.

Update batch entry, REPL initialization/import resolution, and shared baked-set compilation to consume that collection. Remove the portable export/body reconstruction when all callers have moved. Keep compile-time macro interfaces derived through ordinary library compilation, including private/transitive transformers; do not restore the historical workaround of copying every macro into every library body. Preserve gensym reset, unit compilation order, and interface serialization so full unit IR parity remains meaningful.

Alternative: embed only `base.sld`, as #31 originally suggested. The compiler now bakes a set, so that leaves a second derivation for other members. Embedding raw prelude alongside the new forms would retain duplicate payload and permit divergent behavior.

### 3. Generation precedes the explicit assembly barrier

During explicit `make regen`, build the generator with the seed compiler from the shared source and selected declaration, generate into a temporary tree, validate it, and assemble compiler source from that generated set. The generator must use ordinary language facilities available in the existing seed and must not call the new baked-form compilation interface. This breaks the potential bootstrap cycle. Commit the generated members with the corresponding regenerated bootstrap modules after convergence.

Plain `make` continues to build from committed IR. It does not invoke generation or regen. A clean build can supply `build/emit` for the native freshness guard. The guard generates into a temporary root and compares all declared files and orphan membership without repairing the checkout. Chez runs the same generator only for explicit reference parity; an explicitly requested Chez check fails when Chez is unavailable.

Extend the authoritative input inventory, classification, source fingerprinting, isolated source snapshot, and independent-host assembly for all new generator/wrapper/baking inputs. Neither a stale committed `.sld` nor a matching dirty source/IR pair bypasses isolated generation verification. Keep performance-proof reuse scoped to one validated invocation.

### 4. Cover current guards, with positive controls

Use one otherwise-valid fixture per mutation. Assert exit status, the specific diagnostic category, and the offending name or row. Keep stdout, stderr, status, and fixture identity in failure reports. Exercise fixtures under Emit in the native profile and under Chez in targeted reference verification. Copy inputs into a temporary tree and never mutate source files during a check.

Cover stale private/assigned names, repeated assignments, unknown or repeated homes, both elsewhere mismatches, and the seven builtin-surface/ownership checks currently present. Audit duplicate-export detection too: if upstream checks make it unreachable, document the proof and remove the redundant guard rather than inventing an invalid harness that passes on an earlier failure. Private macros, supported re-exports, overlapping internal/public homes, and normal declarations are success controls. The removed rule forbidding private macros stays removed.

### 5. Preserve observable behavior and narration

No library surface or executable behavior changes are intended. Follow `docs/OUTPUT.md`: inputs, output destinations, member/export counts, bytes, and elapsed durations on stderr; quiet suppresses narration, errors remain visible, data bytes stay independent of verbosity. Measure embedded source size, bootstrap IR size, compiler executable size, and a small standalone executable before and after on the same toolchain. No new dependency or generated source payload should reach user executables through this refactor.

## Risks / Trade-offs

- Host printer differences can change literals or generated bytes: use shared serialization and fixtures covering escaping, special symbols, and numeric data; compare every member byte-for-byte across hosts.
- Compile order changes can perturb labels and interfaces: retain deterministic dependency and body order; compare normalized full unit IR and readable interfaces, including `(scheme base)`.
- A stale seed can obscure changes: keep the generator compatible with existing seed facilities, verify generation independently, run explicit convergence, and require isolated source comparison.
- Generator refactoring broadens #40 beyond its original seven guards: inventory the live guards, keep success controls, and report any proven redundant removal explicitly.
- Removing raw prelude readers can lose macro context: exercise private helpers, imported macros, re-exports, and artifact round trips through all commands.

## Migration Plan

1. Establish portable generation and positive/negative fixture parity before switching embedding.
2. Move all baked consumers together and update assembly/proof inputs. Finish compiler-source edits and run focused source units before the regen barrier.
3. Run formatting on edited covered files, inspect its scope, then explicitly regenerate. Do not mix a whole-set reformat into the change. After regen, complete validation before editing compiler inputs again.
4. Run full native regression, source units, classified targeted reference suites, and isolated source consistency. Include no-manifest checks from an unrelated directory for all four commands, REPL once-only initialization, no-prelude checks, and a moved standalone executable.
5. Add one patch VERSION bump and matching changelog section during implementation. Retain reports and size measurements. Rollback reverts source, generated members, and bootstrap modules together; never combine bootstrap files from different source states.
