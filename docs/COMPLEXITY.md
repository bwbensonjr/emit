# Code Complexity Catalogue

A reproducible catalogue of the code in this repository, classified by **component**,
**role**, and **language**. It exists to answer one question honestly: *how much code is
there, and how much of it did we actually write by hand?*

A raw line-of-code total is misleading here. Most of the tree is **not** hand-authored
system code — it is generated LLVM IR (the committed compiler bootstrap snapshots),
vendored third-party code, an imported language-standard reference, and OpenSpec tracking
history. The catalogue below separates those roles so the **authored subtotal** — the
compiler, runtime, standard library, and tooling we maintain — stands apart from the
full-tree total.

> **LOC is a coarse proxy for complexity.** Line counts measure *volume*, not cognitive or
> cyclomatic difficulty. Use this catalogue to see *where* the code is and *what kind* it
> is, not to rank difficulty. The role and component split is the deliverable; the headline
> number is not.

## Roles

Every tracked file is assigned exactly one role. Symlinks are skipped — they carry no
lines of their own, and counting one would double-count its target (`AGENTS.md ->
CLAUDE.md`), which is catalogued under its own path.

| Role | Meaning |
|---|---|
| **authored** | Hand-written compiler / runtime / stdlib / build + dev tooling source — the headline subtotal. |
| **docs** | Hand-written project prose (README, `docs/`, design notes). |
| **generated** | Build artifacts checked into the tree: `bootstrap/*.ll`, plus the files under `lib/` that carry a `GENERATED` marker (the Unicode tables and the derived `.sld` export lists). |
| **vendored** | Third-party code copied into the tree — the Unicode Character Database under `vendor/unicode/`, and the chibi-scheme R7RS-small suite under `test/r7rs/`. |
| **reference** | External material reproduced for convenience (imported specs, genesis). |
| **tracking** | OpenSpec changes + specs — process history, not system code. |
| **config** | Agent / editor / repo configuration (`.claude`, `.agents`, `.gitignore`, `LICENSE`). |
| **test** | Test programs and harnesses. |
| **demo** | Example programs under `demos/`. |
| **spike** | First-party experiments (none currently — the rule remains for any future spike). |
| **other** | Anything the rules do not match — a visible gap to fix, never dropped. |

## Regenerating

The tables below are produced by [`tools/complexity.sh`](../tools/complexity.sh) and
regenerated with:

```sh
make catalogue
```

When code moves, the numbers below go stale until you regenerate. If a file lands in the
wrong component or role — or in `other` — fix the **classification policy** (the single
ordered `case` block in `tools/complexity.sh`), then rerun `make catalogue`. That script is
the one place the authored-vs-generated-vs-vendored policy lives.

Each regeneration also appends the current totals to [`complexity-history.csv`](complexity-history.csv)
— an append-only, long-format ledger (`timestamp,commit,dimension,key,files,loc`) of the
whole-tree total, each role, and each component over time. A snapshot is recorded only when
the numbers change from the last one, so the history tracks real movement rather than every
run. The history file is itself excluded from the count (a metric that included its own
ledger could never settle).

## Reading the numbers

<!-- Hand-authored interpretation. Refreshed alongside the tables (the complexity-catalogue
     skill updates this section); it lives OUTSIDE the generated markers so regenerating the

- **The system we maintain is small.** 20,246 authored LOC across 40 files — 4.3% of the
  full tree. The other 96% is generated IR and generated stdlib tables, a vendored Unicode
  database, OpenSpec tracking history, an imported language-standard reference, tests, and a
  vendored conformance suite. Complexity work belongs in the authored components.
- **The authored subtotal changed meaning at this snapshot; read the history CSV with that
  in mind.** Six of the twelve files under `lib/` carry a `GENERATED` marker and were being
  counted as hand-written stdlib source. They are now `generated` (component
  `stdlib-generated`, 3,137 LOC over 6 files): `lib/scheme/char-data.scm` (2,397) is a
  Unicode table emitted by `tools/gen-unicode-tables.ss`, and the five `.sld` files
  (`base` 402, `emit/internal` 216, `cxr` 64, `file` 35, `read` 23) are export-list wrappers
  emitted from `src/prelude.scm`, whose bodies are already counted once under
  `compiler-core`. The classification is driven by the marker itself, not a filename list —
  the same signal `test/scheme-base-gen-check.sh` and `test/unicode-data-gen-check.sh` scan
  for when they assert those bytes are byte-identical to a fresh generation — so a new
  generated library classifies correctly the day it lands. This is a reclassification: no
  code was deleted, and it is the same kind of step as the `docs`/`reference` split noted at
  the bottom of this section.
- **On a comparable basis the authored system grew by ~1,038 LOC, not by 307.** The previous
  snapshot's 19,939 included 731 LOC of generated `.sld` wrappers, so it is ~19,208 under
  today's rule; `char-data.scm` did not exist yet. The +1,038 over the 17 commits since
  `4fb3269` breaks down as `tools` +332, `runtime` +256, `stdlib` +224, `compiler-core`
  +113, `native-drivers` +53, `compiler-passes` +49, `build` +11. After the 66% jump the
  last snapshot recorded, this interval is consolidation.
- **The tree grew 70,028 LOC and almost none of it is ours.** 399,722 → 469,750, of which
  +58,165 is the vendored Unicode Character Database and +3,137 the generated stdlib tables
  it feeds. That is why the authored *share* fell 5.0% → 4.3% while the authored system was
  growing: the denominator moved, not the numerator.
- **`vendored` is now the third-largest mass in the tree** — 60,721 LOC over 11 files, 12.9%
  — and it did not exist as a meaningful category two snapshots ago. `vendor/unicode/17.0.0/`
  (58,165) is the UCD, downloaded verbatim, pinned by `CHECKSUMS.sha256`, and read only by a
  generator; `test/r7rs/r7rs-tests.scm` and its license (2,556) are the chibi-scheme
  R7RS-small suite. Both are classified ahead of the rules for the directories they sit in,
  because the authored-vs-not split is the whole point of the catalogue.
- **`bootstrap/*.ll` still dominates the raw total** — 273,061 LOC, 58% of the tree, five
  artifacts, generated. It is the compiler compiled to LLVM IR, checked in as a stage-0
  bootstrap input, not code anyone edits.
- **Three languages carry the system**: Scheme 13,229, C 3,121, C++ 2,863, with Shell 790 and
  Make 243 for the build. The heaviest files remain one per language —
  `src/runtime/runtime.c` (3,121, the largest authored file), `src/emit.cpp` (2,664), and
  `src/prelude.scm` (2,477), with `src/emit.ss` (1,837) behind them.
- **The 13,229 authored Scheme lines sit in exactly 32 files, and that is the covered set the
  formatter claims.** The `pitch-source-formatting` change resolves its own candidate list
  independently — `src/*.{scm,ss}`, `src/passes/*.ss`, the hand-authored `lib/**/*.sld`,
  `tools/*.ss`, `emit-libs.scm`, minus anything marked generated — and lands on the same 32
  files and the same line count this table now reports. Two policies written for different
  purposes agreeing to the line is a useful check on both.
- **`compiler-core` remains the largest authored component** (Scheme, 10,286 over 15 files:
  codegen, the Chez-hosted `compile.ss` driver, the parser, the REPL core, the prelude, and
  the declared `(scheme base)` surface). It moved only +113 this interval — the module-system
  build-out that added +3,782 to it last time has settled.
- **`runtime` grew +256, and a third of that is two quadratics removed.** `runtime.c` is the
  one authored file that is also the one place performance debt keeps landing: the
  `reduce-runtime-quadratics` work (net +80) replaced `rt_intern`'s linear table scan with an
  open-addressed hash set and made `rt_string_set` write in place, recorded as P19 and P20 in
  `docs/PERFORMANCE.md`. P21 — string ports backed by a libc `FILE` — is recorded open there
  and is the one item that asks for its own OpenSpec change.
- **The `stdlib` row now means what it says**, and it is small: 274 LOC over 6 hand-authored
  R7RS libraries (`scheme char` 112, `emit filesystem` 48, `scheme case-lambda` 28,
  `scheme inexact` 50, `scheme process-context` 19, `scheme write` 17). The standard
  library's real weight is in `src/prelude.scm`, under `compiler-core`.
- **`test` is the largest non-generated mass after tracking** at 16,110 LOC over 143 files —
  still growing faster than the code it covers, and still mostly conformance and
  module-pipeline gating rather than unit tests.
- **OpenSpec tracking is the second-largest mass overall** — 73,535 LOC over 784 files, more
  than three times the authored system, and mostly archived change history (55,208 across 728
  files). Expected for a spec-driven project, and it grows monotonically by design.
- **Two older counting rules worth knowing when reading the history CSV.** Symlinks are
  skipped: `AGENTS.md -> CLAUDE.md` was double-counting its target's lines as project prose.
  And the `docs`/`reference` split changed *meaning*, not content, between the `ef2e2da` and
  `033e13f` snapshots: the imported R7RS-small report moved from a single `docs/r7rs-small.md`
  to a per-chapter `docs/r7rs/` tree, so ~10.7K LOC stopped being counted as hand-written
  project prose. No prose was deleted at either step.
